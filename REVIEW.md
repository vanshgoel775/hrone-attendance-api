# REVIEW.md

Defects found in the starter `app/main.py`, and what I did about each.

| # | Where | What is wrong | How you'd notice it | How I fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` | Builds the shift start with `punch_in.replace(hour=h, minute=m)` on a UTC/naive value, so `shift_start` (an IST time) is read as UTC. Lateness is off by 5h30. | Sample 2: punch-in 10:05 IST = 04:35Z, shift 09:30. Start becomes 09:30Z, the difference is negative and the result is 0, expected 35. | Shift start is built as an IST instant for the attendance date (`shift_moment`); everything is aware datetimes. |
| 2 | `compute_late_minutes` | The grace test runs on the already-floored whole minutes (`minutes > 10`), so "strictly more than 10:00" is wrong for 10:00 < t < 11:00. Seconds are not truncated first either. | 09:40:01 on a 09:30 shift returns 0, R2 says 10. 09:40:00.900 must count as 09:40:00. | Compare whole seconds (`> 600`), then `// 60`. Punched_at is truncated to seconds on input (`instant_from_ms`). |
| 3 | `compute_late_minutes`, `compute_overtime` | Overnight shifts are not handled: the shift start/end are always placed on the punch's own calendar day. | Shift 22:00-06:00, punch-in 21:55 on the 6th, punch-out 06:40 on the 7th: end is placed on the 6th, so overtime is about 1480 instead of 40. | `attendance_date` applies R1 (an early-morning punch-in belongs to the previous day's shift); the shift end is moved to the next day when `shift_end <= shift_start`. |
| 4 | `compute_overtime` | No 30-minute minimum (R3). Also subtracts an aware `end` from a possibly naive `punch_out`, which raises `TypeError` (500). | Punch-out 18:35 on a 18:30 shift gives 5, expected 0. | Floor minutes, return 0 below 30; all datetimes are timezone-aware (client uses `tz_aware=True`). |
| 5 | `compute_work_hours` | Uses float `round()`: not half-up, and binary floats make ties unpredictable (R4). Does not truncate to seconds. | 54 seconds worked is 0.015 h: `round(0.015, 2)` returns 0.01, R4 expects 0.02. | Integer arithmetic: `(seconds*100 + 1800) // 3600` = hundredths, half-up exactly. `half_day` uses the rounded value (R5). |
| 6 | `EmployeeIn` | No validation at all: any emp_code, "25:99" shift times, `joined_on="soon"`, empty name, `shift_start == shift_end` are accepted. | `POST /employees` with `{"emp_code":"x","joined_on":"soon",...}` returns 201, expected 422. | Pydantic constraints (patterns, lengths, valid calendar date, start != end). |
| 7 | `create_employee` | Check-then-insert with no unique index: two simultaneous creates both pass the check. `created_at` is `datetime.now()` (naive, server local time) and is returned as an ISO string. | 10 parallel POSTs of the same emp_code give several 201s and duplicate documents. | Unique index on `emp_code`, catch `DuplicateKeyError` -> 409; `created_at` is UTC and returned as epoch ms. |
| 8 | `list_employees` | `skip = page * page_size` skips the first page. `total` counts the whole collection, ignoring `department`. No sort. `page`/`page_size` are not validated (0, negative or huge values). Returns `created_at` as ISO string. | `page=1` returns employees 21-40. `department=Sales` shows `total` of all staff. `page=-1` makes PyMongo raise (500). | `skip=(page-1)*page_size`, `count_documents(query)`, sort by `emp_code`, `Query(ge=1)` / `le=100`, epoch ms. |
| 9 | `punch_in` | Unknown employee: `emp` is `None`, `emp["shift_start"]` raises `TypeError` -> 500. | `POST /attendance/punch-in {"emp_code":"NOPE"}`. | Explicit 404 before any other work. |
| 10 | `PunchInIn` / `punch_in` | `status` is any string (ABSENT, LEAVE, "banana" get stored). `punched_at` accepts floats, numeric strings, seconds-looking values and `0` (treated as "missing" by `if body.punched_at`). Huge values crash `fromtimestamp` (500). | `status:"LEAVE"`, `punched_at:1783312500` (seconds), `punched_at:1.7e12`. | `Literal` status limited to PRESENT/WFH/ON_DUTY; `punched_at` is a strict int in [1e11, 4.1e12] (422 otherwise); `is not None` check. |
| 11 | `punch_in` | `datetime.fromtimestamp(ms/1000)` gives a naive datetime in the server's local zone, with float rounding and microseconds. The date is `ts.date()` in the server zone, not IST, and ignores the overnight rule. | On a UTC server, a punch at 02:00 IST on the 7th is stored on the 6th. | Exact `EPOCH + timedelta(milliseconds=...)`, truncated to seconds; date from `attendance_date` in IST. |
| 12 | `punch_in` | Check-then-insert race and no unique index: two simultaneous punch-ins both pass `find_one` and both insert. | 20 parallel identical requests: several 201s, duplicate (emp_code, date) rows. | Unique `(emp_code, date)` index; `insert_one` and map `DuplicateKeyError` to 409. |
| 13 | `punch_in`, `list_attendance` | Response leaks the ObjectId as `id` (forbidden by the contract) and returns datetimes (ISO strings) instead of epoch ms. Legacy rows lack `half_day`/`history` in the output. | Compare the JSON with the `AttendanceRecord` schema. | `record_out` builds the exact contract shape, with defaults for legacy fields, no id. |
| 14 | `list_attendance` | `find(q)` loads every matching record, sorts in Python, then slices. Sort is by `date` only (no `emp_code` tie-break). Unusable at 100k records. | `GET /attendance` on 100k docs: slow, memory heavy; same-date rows come back in arbitrary order. | Database `sort([("date",-1),("emp_code",1)])`, `skip`, `limit`, backed by index `(date desc, emp_code)`. |
| 15 | `list_attendance` | `page=0` slices `docs[-20:0]` (empty page); `page_size` unbounded; `date_from > date_to` and malformed dates are accepted; unknown `status` silently returns an empty list. | `page=0`, `date_from=2026-07-09&date_to=2026-07-01`, `status=BANANA`. | `Query(ge=1)`, `le=100`; date validation and ordering check -> 422; `status` is a `Literal`. |
| 16 | `/health` | Always returns ok, even when MongoDB is down. | Stop MongoDB, call `/health`: still 200. | Pings MongoDB, 503 on failure. |
| 17 | `MongoClient(...)` / startup | No `tz_aware=True`: every datetime read back is naive, so subtracting aware values raises. No indexes are created at startup, so every query is a collection scan and nothing is unique. | Compare `punch_in` read from Mongo with an aware datetime: `TypeError`. `explain` shows COLLSCAN. | `tz_aware=True`; `ensure_indexes()` at startup (idempotent, tolerant of failures). |

## Looked at and decided it is fine

* `load_dotenv()` with its default `override=False`: variables already set in the real environment win over `.env`, as the contract requires.
* The `IST = timezone(timedelta(hours=5, minutes=30))` constant is correct (no DST in India); I reuse it.
* `status_code=201` on both create endpoints, and popping `_id` from the inserted dict in `create_employee` (PyMongo adds `_id` to the dict in place) are correct.
* The idea of reusing the helper functions is fine, but their bodies were not; they are rewritten as pure functions of `(aware datetime, attendance date, shift)`.
